# AGENT_TASK_DATASET_PAIR — задание: датасет из одной пары ортофотопланов

**Дата:** 2026-08-27 · **Статус:** задание для агента-исполнителя ·
**Контекст:** [DATASET_ORTO_PAIRS_PLAN.md](DATASET_ORTO_PAIRS_PLAN.md) (план,
этапы Р/Г), [DATASET_SPEC_FINETUNE.md](DATASET_SPEC_FINETUNE.md) (формат
пары, §2), [GEOREF_SHIFTS_REPORT.md](GEOREF_SHIFTS_REPORT.md) §6.2 (правило
компенсации).

Задача: реализовать и прогнать конвейер генерации обучающих пар на **одной
паре ортофотопланов — площадка 95** (пилот этапа Г2 плана). Результат —
~700 сэмплов канонического формата + артефакты контроля, по которым
пользователь примет или отклонит конвейер.

Измеренные факты о паре (проверить при старте, числа должны сойтись):

альфа бесполезна (всегда 255); CRS-метка недостоверна, но **обе стороны пары
живут в одной сетке** — для warp внутри пары этого достаточно. Валидное
пересечение дат **21.1 км²**, после эрозии 200 м — **10.75 км²**.

### 0.1. Конвенции и подводные камни (обязательно к прочтению)

1. **Nodata — белый (255), не чёрный.** Маска валидности:
   `(px > 5) & (px < 250)`. Проверять на обоих растрах.
2. **Единицы сетки ≠ метры земли.** Сетка растров — псевдо-меркаторская:
   1 единица сетки = `1/cos(lat)` метров земли. Широту брать обратным
   веб-меркатором от y сетки (R = 6378137): для пары 95 центр
   y ≈ 7 314 350 → lat ≈ 54.76°, `k = 1/cos(lat) ≈ 1.733`. Наземный GSD
   хранения = 0.1707/k ≈ **0.0985 м/пикс**. Все «метры» задания (высоты,
   футпринты, пороги компенсации) — наземные; при работе с сеткой умножать
   на k. k вычислить один раз от центра пары и зафиксировать в логе.
3. **Пиксель = центр** (инвариант проекта №5): координата (0, 0) — центр
   левого верхнего пикселя; главная точка кадра 1024×768 —
   ((1024−1)/2, (768−1)/2) = (511.5, 383.5).
4. Чтение фрагментов: `rasterio` + `windows.from_bounds(...)` +
   `out_shape` + `Resampling.average`, `boundless=True, fill_value=0`.
5. Оси: сетка — x на восток, y на север; изображение — u вправо, v вниз
   (строка растра идёт с севера на юг: `y_grid = top − (row+0.5)·res`).

## 1. Этап Р — поле сдвигов пары (рефайнмент)

Скрипт `refine_pair.py`. Один раз на пару, до генерации.

1. Построить маски валидности обеих сторон на обзорном разрешении 20 м/пикс
   (окно = пересечение bbox), пересечь, эродировать на 200 м (10 итераций).
2. Сетка узлов **1×1 км** по рабочей зоне; узел активен, если ≥ 60% его
   квадрата валидно.
3. В каждом активном узле: прочитать native-кропы A и B 1024² (родное
   разрешение, north-up, один и тот же bbox), градиентные карты (Собель по
   x/y, модуль, клип по 99-му перцентилю, нормировка, обнуление вне маски
   валидности), окно Ханна, **фазовая корреляция** с субпиксельным уточнением
   пика (парабола по 3 точкам). Выход узла: (dx, dy) в единицах сетки +
   высота пика.
4. **Контроль остатка**: применить найденный сдвиг и повторить замер —
   остаточный сдвиг должен быть < 1 м наземных.
5. **Правило компенсации на узел** (все условия сразу, иначе узел пустой):
   |сдвиг| ≤ 12 м наземных; остаток < 1 м; согласие с медианой соседних
   валидных узлов ≤ 3 м. Пустые узлы — со счётчиком и причиной.
6. Выход `aux/shift_field_95.npz`: массивы `xs, ys` (центры узлов, сетка),
   `dx, dy` (единицы сетки), `valid` (bool), `peak`, атрибуты: k, дата,
   git-коммит, глобальная медиана поля (фолбэк-константа пары).
7. Отчёт `aux/refine_95.html`: стрелочная карта поля сдвигов поверх
   обзорного изображения, гистограмма |сдвигов|, счётчики узлов
   (активных/валидных/пустых по причинам).

**Приёмка этапа Р**: ≥ 70% активных узлов валидны; медиана |сдвига| —
единицы метров (по гейту №0 у пары 95 сдвиги малы); поле без диких
выбросов (правило само их режет).

## 2. Этап Г — генерация сэмплов

Скрипт `gen_pairs.py`. Параметры по плану (зафиксированы пользователем):

| параметр | значение |
|---|---|
| камера A | f_px = 3000, кадр 1024×768, гл. точка (511.5, 383.5) |
| высоты H | U(150, 350) м → GSD_A = H/3000 (наземный) |
| yaw | U(−25°, +25°) |
| pitch | U(0°, 10°), азимут наклона U(0°, 360°) |
| перекрытие | covis_frac ∈ [0.30, 0.80] |
| якоря | сетка 60 м по рабочей зоне → прореживание до ~230 |
| сэмплов на якорь | K = 3 (разные H/yaw/pitch/смещение; общий `anchor_id`) |
| квота пары | ~700 принятых сэмплов |

Алгоритм одного сэмпла (якорь = центр кропа B в сетке `(xg, yg)`):

1. **Кроп B**: 1024² native (175 единиц сетки ≈ 101 наземных м), north-up,
   из растра B-даты, центр (xg, yg).
2. **Сэмпл параметров** (H, yaw, pitch, азимут, целевое covis, смещение
   центра A). Кадр A мельче кропа B по земле (51–120 м против 101 м), при
   малых смещениях covis ≈ 1 — поэтому смещение подбирается выносом
   футпринта A к краю/за край кропа B под целевое covis.
3. **Геометрия камеры A** — в локальной наземной системе якоря (метры
   земли, x — восток, y — север, z — вверх; сцена — плоскость z = 0):
   - луч пикселя (u, v): `d_cam = K⁻¹·(u, v, 1)`,
     K = [[3000, 0, 511.5], [0, 3000, 383.5], [0, 0, 1]];
   - ориентация: `R = R_z(yaw) · R_tilt(pitch, азимут)`; конвенцию осей
     камеры (x вправо, y вниз, z вперёд-вниз) и знаки углов **зафиксировать
     в докстринге и покрыть V-тестами** (п. 3) — это главное место ошибок;
   - центр камеры `C = (x_off, y_off, H)`; пересечение луча пикселя с
     плоскостью z = 0 даёт его наземные координаты `(ground_x, ground_y)`;
     перевод в сетку растров: `grid = (xg, yg) + k·(ground_x, ground_y)`
     (компенсация привязки сюда не входит — она добавляется на шаге 5–6).
4. **Рендер A**: обратной выборкой — для каждого пикселя кадра A взять
   точку растра A-даты по построенной сетке (билинейно;
   `upsample_factor = 0.0985/GSD_A`, если > 1 — апсемпл, пишется в мету).
5. **Компенсация**: билинейная интерполяция `shift_field_95` в точке якоря →
   `(dx, dy)` единиц сетки. Якорь вне валидной зоны поля: фолбэк-константа
   пары; если поля нет и константы нет — сэмпл отбрасывается (счётчик).
6. **GT `warp_ab`** (768×1024×2, float16): для каждого пикселя A — его
   наземная точка (шаг 3) → сетка растра (+компенсация) → пиксель кропа B:
   `u_b = (x_grid − left_B)/res − 0.5`, `v_b = (top_B − y_grid)/res − 0.5`.
   `mask_ab` (uint8): точка внутри кропа B ∧ валидность растра A в пикселе
   A ∧ валидность растра B в точке B. NaN в warp вне маски.
7. **Фильтр**: `covis_frac = mask_ab.mean()` ∈ [0.30, 0.80]; вне — новый
   сэмпл смещения (до 5 попыток, потом якорь пропускается со счётчиком).
8. **Запись** `pair_95/pair_95_<anchor>_<k>.npz` по спеке §2:
   `image_a_jpeg` (JPEG q95, RGB — растры одноканальные, реплицировать в
   3 канала), `image_b_jpeg`, `warp_ab`, `mask_ab`, `meta` (json-строка).
   Мета — все поля спеки §2.3 + `height_m, yaw_deg, tilt_deg,
   pitch_azimuth_deg, upsample_factor, compensation_m` (наземные метры),
   `anchor_id` (например `95_a0231`), `scene = "pad_95"`,
   `pair_kind = "cross_season"`, `season_a = "autumn"`,
   `season_b = "spring"`, `covis_frac`, `gsd_a`, `gsd_b = 0.0985`,
   `scale_ratio`, `gen_commit`, `gen_date`. `pinhole` — `"null"` (путь B в
   пилоте не заполняем).
9. **Same-date контроль**: ~15% сэмплов дополнительно генерятся в варианте
   A-дата = B-дата (осень↔осень) с тем же конвейером,
   `pair_kind = "same_date"` — на них warp обязан быть точным по
   построению (используются V-тестами и как контрольная ось).

## 3. V-тесты (писать до генератора — «стенд раньше кода»)

Аналитические, без данных либо на одном кропе; складывать в
`scripts/dataset_pairs/test_gen_pairs.py` (pytest):

- **V1 — тождество**: pitch = 0, yaw = 0, H такое, что GSD_A = 0.0985
  (H = 295.5 м), центр A = центр B, same-date → warp обязан совпасть с
  аффинным пересчётом сеток с точностью < 0.05 px по всей маске.
- **V2 — чистый yaw**: pitch = 0, yaw = 30° (тестовое значение вне боевого
  диапазона допустимо) → warp — поворот вокруг центра кадра; сверить с
  аналитической формулой поворота < 0.05 px.
- **V3 — чистый pitch**: yaw = 0, pitch = 10°, азимут 0/90/180/270 →
  warp — гомография; сверить с cv2-эталоном `getPerspectiveTransform` по
  4 углам < 0.1 px; проверить знак (наклон к северу должен сжимать
  северную часть кадра — зафиксировать в тесте выбранную конвенцию).
- **V4 — круговой тест**: warp_ab + обратный warp_ba (построить обратной
  прогонкой) → композиция тождественна < 0.2 px на валидных пикселях.
- **V5 — covis**: на синтетических смещениях центра сверить фактическую
  `covis_frac` с геометрически ожидаемой ± 0.03.
- **V6 — same-date по данным**: 5 реальных same-date сэмплов → фазовая
  корреляция A(отрендеренный, приведённый к GSD B) против кропа B в зоне
  перекрытия < 0.5 px остатка.

## 4. Артефакты приёмки (по ним принимает пользователь)

1. `aux/refine_95.html` — отчёт этапа Р (п. 1.7).
2. `aux/gen_95_report.html` — отчёт генерации:
   - счётчики: якорей всего/использовано, сэмплов принято/отсеяно по
     причинам (covis, поле сдвигов, попытки), доля отсева;
   - гистограммы осей: H, yaw, pitch, covis_frac, scale_ratio,
     upsample_factor;
   - **галерея 20 случайных сэмплов**: панель «кадр A | кроп B | шахматка
     B-натянутой-по-warp на геометрию A» (формат гейта №0 — дороги обязаны
     продолжаться через границы клеток);
   - 5 same-date панелей отдельно.
3. Лог прогона + версии (git-коммит скриптов, даты).
4. Сводка объёма: число npz, средний размер, суммарный объём (ожидание
   ~700 × 2–2.5 МБ ≈ 1.5–1.8 ГБ).

**Критерии готово**: V-тесты зелёные; приёмка Р пройдена; отсев генерации
< 5% на пилоте (порог мягче боевого, причины — в отчёте); галерея шахматок
без визуальных разрывов на валидных клетках; объём и мета соответствуют
спеке (выборочная проверка `load_pair` из `scripts/convert_ortholoc.py`,
если совместимость читалки требуется — согласовать формат чтения с ней).

## 5. Чего в пилоте НЕ делать

- Не трогать растры GTKAZ/GTNN/GTUH и frame-dataset (тестовый контур).
- Не чинить абсолютную привязку растров (фейковая СК — известная отдельная
  задача; внутри пары она не мешает).
- Не запускать чистку боевым ядром (этап Г2 плана — отдельно, после
  приёмки генератора).
- Не генерить другие пары и не менять диапазоны параметров — они приняты
  пользователем; любые отклонения — вопросом в отчёте, не молча.
