# Как обучать на этом датасете

Практическая часть: что читать из манифеста, как собрать загрузчик, как
сэмплировать, что мерить и чего не делать. Как датасет получен — в
`METHODOLOGY.md`, что доработано в редакции v2 — в `DATASET_OAM_V2_REPORT.md`,
критерии приёмки — в `ACCEPTANCE.md`.

---

## 1. Коротко: что здесь есть

Пара — это `.npz` с двумя изображениями, плотным соответствием A→B и маской
ко-видимости. Разметка **уже в том виде, который тренерам нужен внутри лосса**:
у `romatch` функция `get_gt_warp` из `depth+K+T` строит ровно это — warp плюс
бинарную маску. Поэтому переразмечать ничего не надо, нужен свой `Dataset` и
подмена одного вызова.

| колонка манифеста | зачем при обучении |
|---|---|
| `pair` | имя файла |
| `split` | `train` / `val` / `heldout` — **делить только по ней** |
| `weight` | вес пары в смеси, готов к использованию сэмплером |
| `gt_class` | `exact` / `registered` / `approx` — насколько точна разметка |
| `gt_sigma_px` | ожидаемая ошибка разметки этой пары, px |
| `pair_kind` | `orto_basemap` (боевой тип) / `same_source` (контроль) / `cross_date` |
| `slice` | `relief_xmodal` — пары из карт рельефа, вес 0 |
| `geo_cluster`, `scene` | территория: нужны, если будете переделывать сплиты |
| `covis_frac`, `height_m`, `tilt_deg`, `scale_ratio` | для разрезов метрик |

## 2. Загрузчик: минимальный рабочий вариант

```python
import cv2, json, numpy as np, torch

class OamPairs(torch.utils.data.Dataset):
    def __init__(self, root, manifest, split, size=560):
        import csv
        rows = list(csv.DictReader(open(manifest, encoding="utf-8")))
        self.rows = [r for r in rows
                     if r["split"] == split and float(r["weight"]) > 0]
        self.root, self.size = root, size

    def __len__(self):
        return len(self.rows)

    def __getitem__(self, i):
        r = self.rows[i]
        d = np.load(f"{self.root}/{r['pair']}", allow_pickle=False)
        a = cv2.imdecode(d["image_a_jpeg"], cv2.IMREAD_COLOR)[..., ::-1]
        b = cv2.imdecode(d["image_b_jpeg"], cv2.IMREAD_COLOR)[..., ::-1]
        warp = d["warp_ab"].astype(np.float32)     # (H, W, 2) в пикселях B
        mask = d["mask_ab"].astype(bool) & np.isfinite(warp).all(-1)

        ha, wa = a.shape[:2]
        hb, wb = b.shape[:2]
        s = self.size
        # ресайз обеих сторон к квадрату + пересчёт координат warp:
        # масштаб по осям разный, и забыть об этом — самая частая ошибка
        warp = cv2.resize(warp, (s, s), interpolation=cv2.INTER_NEAREST)
        warp[..., 0] *= s / wb
        warp[..., 1] *= s / hb
        mask = cv2.resize(mask.astype(np.uint8), (s, s),
                          interpolation=cv2.INTER_NEAREST).astype(bool)
        a = cv2.resize(a, (s, s), interpolation=cv2.INTER_AREA)
        b = cv2.resize(b, (s, s), interpolation=cv2.INTER_AREA)

        return {
            "im_A": torch.from_numpy(a.copy()).permute(2, 0, 1).float() / 255,
            "im_B": torch.from_numpy(b.copy()).permute(2, 0, 1).float() / 255,
            "warp": torch.from_numpy(warp),          # пиксели B
            "mask": torch.from_numpy(mask),
            "weight": float(r["weight"]),
            "sigma_px": float(r["gt_sigma_px"]),
        }
```

Три места, где легко ошибиться:

1. **Маска ресайзится `INTER_NEAREST`**, не билинейно: билинейная интерполяция
   размывает границу ко-видимости и добавляет пикселей, у которых соответствия
   нет.
2. **Координаты `warp` масштабируются вместе с изображением.** Сторона B имеет
   768–2048 px, и приведение к квадрату меняет масштаб по осям по-разному.
3. **`isfinite` проверяется даже внутри маски.** Маска и конечность значений
   хранятся отдельно; опираться надо на оба признака.

## 3. Подмена GT в тренере

### RoMa v1 (`romatch`)

GT строится **внутри лосса**, а не в датасете: `losses/robust_loss.py`,
метод `forward`, вызов `get_gt_warp(im_A_depth, im_B_depth, T_1to2, K1, K2,
H, W)`. Он возвращает `(gt_warp, gt_prob)` — нормализованные координаты и
бинарную маску. Наш `warp` — то же самое, только в пикселях B.

```python
def gt_from_batch(batch, H, W):
    """Замена get_gt_warp: наш warp уже готов, надо только привести форму."""
    warp = batch["warp"]                       # (B, h, w, 2) в пикселях B
    mask = batch["mask"].float()
    warp = torch.nn.functional.interpolate(
        warp.permute(0, 3, 1, 2), size=(H, W), mode="nearest").permute(0, 2, 3, 1)
    prob = torch.nn.functional.interpolate(
        mask[:, None], size=(H, W), mode="nearest")[:, 0]
    # в нормализованные координаты той же конвенции, что у romatch:
    # линейка centers, align_corners=False
    w_img, h_img = batch["im_B"].shape[-1], batch["im_B"].shape[-2]
    x = warp[..., 0] * 2 / w_img - 1
    y = warp[..., 1] * 2 / h_img - 1
    return torch.stack([x, y], dim=-1), prob
```

Лосс вызывается на каждом масштабе (1, 2, 4, 8, 16) со своими `H, W` — поэтому
приведение делается внутри, а не один раз.

### LoFTR

Обучающего кода в установленной `kornia` нет — она inference-only. Нужен
оригинальный репозиторий или форк MINIMA; точка подмены там `spvs_coarse` /
`spvs_fine`, логика такая же: вместо построения соответствий из `depth+K+T`
читать готовый `warp` и маску.

### RoMa v2

В пакете `romav2` нет ни лосса, ни цикла обучения — только инференс и
бенчмарки. Дообучение потребует кода авторов либо собственного цикла. По
измерению на этом корпусе она худшая из пяти на боевом типе пары, так что
приоритет низкий.

## 4. Сэмплер: колонка `weight` готова к использованию

```python
rows = train_dataset.rows
weights = [float(r["weight"]) for r in rows]
sampler = torch.utils.data.WeightedRandomSampler(
    weights, num_samples=len(rows), replacement=True)
```

Веса устроены так:

| класс | вес | доля в смеси | почему |
|---|---|---|---|
| `registered` | 1.0 | 83 % | боевой тип с подтверждённой привязкой — основной сигнал |
| `approx` | 0.3 | 5 % | компенсация привязки — константа площадки; вчетверо чаще оказывались среди брака |
| `exact` | 0.5 | 12 % | `same_source`: контроль забывания, а не сигнал — линия RoMa решает его на `inl3` = 1.00 |
| — | 0.0 | 0 % | пары из карт рельефа (`slice = relief_xmodal`): содержание не фотографическое |

## 5. Что мерить

Всё зафиксировано в `ACCEPTANCE.md` **до** обучения — это защита от выбора
метрики задним числом. Кратко:

- **решающие**: `inl5` и доля успешных пар на боевых парах `heldout`
  (база RoMa v1: `inl5` 0.43, успех 0.43 при
  n = 749; потолки 0.73 и ~1.0);
- **справочные**: EPE, `inl10`, разрезы по высоте, наклону, разнице курсов;
- **не использовать `inl3`**: его потолок 0.37, он меряет
  преимущественно шум разметки;
- **контроль забывания**: `same_source` не должен просесть ниже `inl3` 0.99;
- **прогресс считать нормированно**: `(стало − база) / (потолок − база)`;
- **порог значимости**: различимо от 0.025 по доле
  успеха при парном сравнении.

Потолки существуют потому, что у самой разметки есть измеренное расхождение с
независимым арбитром. Даже идеальная модель не покажет EPE ниже него.

**Выбор чекпоинта — по `val`.** `heldout` расходуется один раз, на приёмке.

## 6. Чего не делать

- **Не делить по парам или по площадкам.** Только по `split`: он построен по
  географическим кластерам, потому что соседние вылеты снимают смежную
  территорию, и площадка из train может оказаться в трёхстах метрах от
  площадки приёмки.
- **Не трогать `heldout` до приёмки.**
- **Не учить на парах с `weight = 0`** — это карты рельефа, а не снимки.
- **Не считать `gt_sigma_px` шумом, который можно «дообучить».** Это предел
  источников: геопривязка ортоплана, мозаика подложки, параллакс зданий.
- **Не смешивать пороги между видами пар.** На `same_source` разметка точна до
  сотых пикселя, на боевых парах — единицы пикселей; один и тот же порог
  инлайера означает на них разное.

## 7. Известные ограничения

1. **Сезонная ось почти не покрыта.** Настоящий кросс-дат — 26 пар
   (`pair_kind = cross_date`), и это измерительная ось, а не обучающий сигнал.
   Синтетическая перекраска на `same_source` разрыва почти не создаёт:
   корреляция яркости сторон 0.99 против 0.99 у неперекрашенных.
2. **Нет высот ниже 175 м.** Боевой трудный режим — 90–110 м; его в корпусе
   нет намеренно: на такой высоте кропы однородны, и учить на них — учить
   угадывать. Измерительный срез отложен.
3. **Плоская модель земли.** Кадр рендерится на плоскость z = 0, метрического
   DSM нет; на пересечённой местности это добавляет ошибку, растущую с наклоном.
4. **Обратного поля B→A нет.** Симметричный режим RoMa (`forward_symmetric`)
   потребует его построения.
5. **Сторона B до 2048 px** — датасет тяжелее необходимого; при узком месте по
   IO имеет смысл заранее пересжать до входного разрешения тренера.

## 8. Проверка перед запуском

```bash

python open_orto/scripts/dataset_summary.py --root openaerialmap_dataset
```

Ручной чек-лист:

- [ ] `split` читается и используется; `heldout` не участвует в обучении;
- [ ] маска ресайзится `INTER_NEAREST`, координаты `warp` масштабируются;
- [ ] сэмплер учитывает `weight`, пары с нулём исключены;
- [ ] решающие метрики и потолки взяты из `ACCEPTANCE.md`, а не назначены заново;
- [ ] контроль забывания на `same_source` включён в цикл валидации.
