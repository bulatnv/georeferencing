## Что работает сейчас

Весь конвейер из [PIPELINE.md](PIPELINE.md) собран и проверен на синтетике:

- **Одиночная локализация** (`localize`): подложка из сети (Esri-тайлы) →
  приведение масштабов → грубый уровень (перебор окна **или** retrieval-индекс)
  → точный уровень (матч + субпиксельный ECC) → цикл переуточнения масштаба →
  калиброванная оценка качества (ковариация центра + эллипс + статус).
- **Retrieval-этаж** (`retrieval.py`): индекс местности с перекрытием и
  ротационной аугментацией, Recall@K, сигнал уникальности → флаг отказа,
  персистентность индекса. Энкодер сменный: стенд-`AveragePoolEncoder` заведён,
  `DinoV2Encoder` готов (gated по torch).
- **Сменное ядро матчинга**: SIFT/AKAZE (классика) + `LightGlueMatcher`/
  `LoFTRMatcher` (обучаемые, gated) — за одним интерфейсом.
- **Последовательностный режим** (`sequence.py`): визуальная одометрия + EKF на
  `(east, north, heading)` с привязкой дрейфа якорями — для низких высот.
- **Стенд**: одиночная сетка, лестница возмущений L1–L4, синтетические
  траектории, Монте-Карло калибровка ковариации, регресс отказа на однородной
  сцене.

```python
from aero_geoloc import localize, Camera, Prior, TileCache
from aero_geoloc.basemap import TileBasemap

result = localize(image, camera, prior, TileBasemap(cache=TileCache("tiles")))
print(result.status, result.center_lat, result.center_lon, result.error_ellipse_m)
```

## Измеренная точность

- **Субпиксельный refinement** (сетка 120): медиана ошибки центра
  0.505 px → **0.011 px** (0.004 м); курс макс 0.003°; масштаб макс 0.014%;
  120/120 без ложняков. SIFT и AKAZE после ECC совпадают (0.011 px).
- **Coarse-to-fine на реальных тайлах Esri** (широкий приор, даунсемпл ×2):
  ошибка 0.1 см, 1339 инлайеров.
- **Цикл масштаба** (ошибка высоты ×2): без цикла 4.48 см / 15 инлайеров;
  с циклом 0.30 см / 24 инлайера, высота восстановлена (1200 м).
- **Калибровка ковариации** (Монте-Карло): покрытие 1σ/2σ 0.384/0.857 против
  номинала 0.393/0.865, средний Махаланобис² 2.04.
- **Recall@K** (retrieval, стенд-энкодер): Recall@5 = 1.0, Recall@3 ≈ 0.8;
  порог уникальности отделяет разрешимую местность от однородной с балансной
  точностью 0.88.
- **Лестница возмущений** (точка перелома): AKAZE устойчивее SIFT на L2
  (блюр/шум, ~2.0 vs ~0.7), SIFT — на L3 (спектр, 33% vs 0%); провалы
  комплементарны.
- **VO/EKF**: VO восстанавливает заданное движение; якоря удерживают смещённый
  дедрекон; сквозной VO+EKF держит траекторию в пределах метров.

## Ключевые решения и находки (не выводятся из чтения кода)

1. **ECC — главный рычаг точности**; после него точность не зависит от матчера
   (SIFT ≡ AKAZE = 0.011 px). Выбор матчера — по устойчивости к appearance gap.
2. **Подложку не интерполируем**: целочисленный кроп мозаики, фактический центр
   (до 0.5 px) отражён в `Georef`.
3. **Зум точного уровня — «ближайший» + отбор по инлайерам в цикле**, а не
   «детальнее»: у границы зума правило `mpp ≤ GSD` перепрыгивало бы уровень.
   В `zoom_for_mpp` эпсилон против дрожания на границе.
4. **Ковариация калибрована для СЛУЧАЙНОЙ ошибки**; систематический сдвиг
   (доминирует на L0, смещает L1/L4) она не видит → на L1/L4 overconfident.
   Осмысленная сквозная калибровка — на лестнице, не на L0. В боевом режиме
   (`refine=True`) эллипс консервативен (не overconfident).
5. **SIFT vs AKAZE — измерением**: провалы комплементарны (см. лестницу).
   Гипотеза «AKAZE хрупче к gap» опровергнута для L2, подтверждена для L3.
6. **Сигнал уникальности — с пространственным подавлением**: зазор до
   **далёкого** двойника, а не top-2 (соседняя перекрывающаяся клетка — то же
   место). Сырой зазор путал соседей с двусмысленностью.
7. **VO кадр-к-кадру**: `Δyaw = поворот подобия`, `ΔENU = GSD·R(prev_yaw)·d` —
   формула выведена и проверена против известного движения.
8. **Соглашения фаз 0–1** в силе: «центр пикселя»; расхождение
   `ground_mpp`/`haversine_m` 0.11% (конвенция радиусов); AKAZE в `xfeatures2d`.

## Границы, которые держатся сознательно

- **Приоры — ограничения**: кандидат/решение вне диска ±3σ отбрасывается; низкая
  уникальность retrieval → отказ до матчинга.
- **Честный отказ дороже красивой точки**: однородная сцена → `NOT_LOCALIZED`;
  бедный кадр в последовательности → рост неопределённости, а не угадывание.
- **Стенд раньше кода**: каждая метрика (калибровка, Recall@K, лестница,
  формула VO) существует до/вместе с алгоритмом и проверяется против эталона.
- **Тяжёлые ядра gated**: DINOv2/LightGlue/LoFTR грузят torch лениво; без него
  пакет импортируется и тестируется, а вызов даёт понятную ошибку (как сеть).

## Валидация на реальных бортовых кадрах (torch + LightGlue)

Пайплайн проверен на настоящих снимках DJI против Esri — это тот самый
appearance gap борт↔спутник, которого нет на синтетике. Загрузчик `drone.py`
(EXIF/XMP → камера, GPS, курс), харнесс `scripts/localize_real.py`.

**Что подтвердилось:**
- **★ ИСХОДНАЯ ЗАДАЧА: локализация из грубого приора ±2 км** (`scripts/
  localize_wide.py`). GPS — только истина; приор искусственно сдвигается. Кадр
  00049 с приором, сдвинутым на **1 и 2 км**: DINOv2-индекс региона (5 км, ~6000
  клеток) схлопывает диск в top-K, LightGlue уточняет → ошибка **9.1 м (сдвиг
  1 км)** и **9.4 м (сдвиг 2 км)** vs истина. Два условия: (1) клетки индекса
  достаточно **финер** (z18: recall 50–64 м; z17 грубоват — 215 м, точный
  уровень не дотягивался); (2) **мультигипотезность** top-K — истинная клетка
  бывает не top-1 (на поле top-1 — ложное совпадение), а точный уровень + гейт
  приора отсекают ложные. На самоподобной местности (поля) уникальность ~0 —
  честный признак трудности, но многостадийная валидация всё равно находит верную.
- **VPR-энкодер MegaLoc снял узкое место Этажа 1** (`MegaLocEncoder`, замена
  сырого DINOv2 одной строкой — тот же протокол `Encoder`). A/B на едином стенде
  (`scripts/compare_encoders.py`), метрика — ранг верной клетки:

  | Кадр | DINOv2 (сырой) | MegaLoc (VPR) |
  |---|---|---|
  | DRZ_19206 (город) | ранг **506**/2116 → отказ | ранг **2**/2116 → **4.2 м** |
  | 00049 (поле) | ранг **139**/2209 | ранг **1**/2209 |

  Городской кадр DRZ_19206, ранее `not_localized` из-за провала retrieval (верная
  клетка тонула на 506-м месте у сырого CLS-токена), теперь локализуется на
  **4.2 м** из приора в 1 км. Обученная агрегация (DINOv2-B + SALAD, обучен на
  5 датасетах) поднимает верную клетку в top-K там, где сырой эмбеддинг её топил.
  Дополнительно вскрыт порог Этажа 2: низковысотный кросс-дата кадр даёт ~7–8
  similarity-инлайеров при верной позе (3–4 м) — `min_inliers=10` их отвергал,
  `min_inliers=6` пропускает (в `localize_wide.py` теперь параметр).
- **Дальность приора 1–3 км держится** (DRZ_19206, MegaLoc). Точность позы
  стабильна ~3.6–4.2 м, но ранг верной клетки у ретривала растёт с регионом, и
  под него расширяется `--top-k` (цена — O(K) матчей LightGlue):

  | Приор | Ранг верной клетки | Клеток | top-K | Ошибка |
  |---|---|---|---|---|
  | 1 км | 2 | 2116 | 5 | 4.2 м |
  | 2 км | 49 | 6084 | 60 | 3.7 м |
  | 3 км | ≤150 | 12100 | 150 | 3.6 м |

  Вывод: Этаж 2 точен, как только клетка доставлена; предел широкого приора —
  **различительность дескриптора Этажа 1 при росте числа дистракторов**. Чистое
  масштабирование до 3–5 км — это PCA→~1024 + доменный словарь/FAISS (устранить
  и деградацию ранга, и O(K)-стоимость), а не только брутфорс top-K.
- **Обучаемое ядро оправдано измерением.** На паре дрон↔Esri (Германия, поле,
  лето↔весна): SIFT — 0 инлайеров, LoFTR — 0, **LightGlue — 54**. Локализация:
  ошибка **9 м** vs GPS (георефа Esri + GPS + наклон 3.8°), эллипс 0.1 м, статус
  `LOW_CONFIDENCE` — честно, фотометрический NCC низок на разных сезонах.
- **Оба этажа связаны на реальных данных.** DINOv2-индекс региона Esri находит
  верную клетку (Recall@1: top-1 в 60 м, где стенд-энкодер — в 189 м), а сквозной
  `localize(index=DINOv2, matcher=LightGlue)` доводит до **8.1 м** vs GPS —
  кандидата даёт retrieval (Этаж 1), позу уточняет LightGlue (Этаж 2). Оба
  обучаемых ядра за интерфейсами `Encoder`/`Matcher`, обвязка не тронута.
- **Две реальные доработки пайплайна** (обе в тестах): клампинг зума точного
  уровня к максимуму провайдера (на 90–180 м кадр в 5–18× детальнее подложки);
  предповорот кадра к северу на −yaw (`prerotate=True`) — LightGlue/LoFTR не
  инвариантны к повороту, а бортовой кадр развёрнут.
- **Честный отказ на пределе gap.** Кросс-сезонный кейс (голые весенние деревья
  ↔ летняя листва, скрывающая структуру) → `NOT_LOCALIZED`, а не ложняк. Косой
  кадр (питч подвеса 0° = горизонт) отсекается как вне надирной модели.
- **Загрузчик расширен на survey-камеры** (`drone.py`): помимо DJI читает
  фотограмметрический XMP `Camera:Yaw/Pitch/Roll` (senseFly/S.O.D.A.) и считает
  AGL как `абс. высота (EXIF) − рельеф (DEM, open-elevation)` — у survey в XMP
  высоты над землёй нет. Находка: конкретные survey-датасеты против Esri **не
  локализуются** — senseFly слишком косой (наклон 16–20°, ректификация не
  спасает: параллакс/контент), S.O.D.A. зимний (снег+наклон). Загрузчик их
  читает, но для валидации против летней Esri они непригодны.
- **Последовательностный режим на реальной серии** (`scripts/run_sequence.py`):
  VO кадр-к-кадру (LightGlue) трекает GPS. Полоса 19 кадров (~500 м) — дрейф
  **1.8%**; **весь полёт 245 кадров через развороты (4.5 км)** — дрейф **4.6%**
  (медиана 34.7 м), траектория-«газонокосилка» повторена. Соседние кадры дрона
  почти без gap. Две находки: (1) **DJI отдаёт курс относительно магнитного
  севера**, а ENU — истинного; без поправки на склонение Уфы (+14.5°) VO
  разворачивало траекторию (дрейф 21%). (2) На **развороте** соседние кадры
  повёрнуты на ~90°, и не-инвариантный матчер проваливается — их выравнивают
  предповоротом на разницу курсов (`headings` в `localize_sequence`): через
  разворот 0→971 инлайер. Поправка склонения — в загрузчике; курс на кадр из
  метаданных. Якоря GPS каждые 5 кадров дожимают дрейф (VO и так хорош).
- **Синтетическая лестница НЕ ранжирует LightGlue честно** (важно). A/B на одной
  сетке (`run_ladder.py`, предповорот для не-инвариантных): точки перелома
  LightGlue — L2(блюр) 1.0 (как SIFT, хуже AKAZE 2.5), L3 0.5 (как SIFT). LightGlue
  обучен на реальных фото, а процедурная сцена + пиксельные возмущения — вне его
  распределения; лестница меряет устойчивость к пиксельной деградации, а не к
  кросс-доменному gap. Настоящее преимущество — на **реальных** данных: 54 инлайера
  vs 0 у классики на дрон↔спутник. Это и есть «синтетика не покажет appearance gap»,
  теперь и для обучаемых ядер — ранжировать матчеры под борт надо на реальных кадрах.
- **Калибровка на объёме реальных кадров** (`scripts/calibrate_real.py`, 74 кадра
  DRZ+Уфа, из них 60 кросс-сезонных): **0 ложных срабатываний** — ни одной
  уверенно-неверной точки, честный отказ держится на реальных данных. Но статус
  оказался **переосторожным**: 8 из 9 верных локализаций (инлайеры 19–121, ошибка
  1–9 м) ложно шли как `LOW_CONFIDENCE`, потому что жёсткий порог NCC (0.3) не
  годится для дрон↔спутник (NCC верных матчей 0.04–0.45). **Исправлено:** `min_ncc`
  вынесен в `localize`; на кросс-домене ~0.05 — тогда сильные матчи получают
  `LOCALIZED`, слабые (низкий NCC, ошибка 9–15 м) остаются `LOW_CONFIDENCE`,
  ложных по-прежнему 0. Надёжный сигнал статуса — инлайеры + эллипс, а не NCC.

**Осталось (нужен объём данных):**
1. **Reliability-диаграмма `confidence`** и порог уникальности retrieval на объёме
   season-matched кадров: сейчас season-matched успехов мало (~8, DRZ), для
   устойчивой калибровки скаляра доверия нужно больше летних/совпавших по сезону.
2. **Лестница на LightGlue** (сдвиг точки перелома дальше классики) — веса готовы.
3. **Кросс-сезонный gap и рельеф**: подложка под сезон кадра / dense-матчинг;
   DEM/DSM для параллакса на низкой высоте.
4. **Абсолютная точность** по контрольным точкам (пол `systematic_floor_m`).

## Известные шероховатости (не блокеры)

- Целевой «Быстрый старт» в [README.md](README.md) показывает `basemap="esri"`
  строкой и путём к файлу; фактический `localize` принимает объект-источник и
  массив кадра — тонкой обёртки «строка/путь → источник/изображение» пока нет.
- Камеры из README (f_px≈697) и PIPELINE (f_px≈3000) — разные; расхождение в
  документации намеренно не устранялось, решение за владельцем.
