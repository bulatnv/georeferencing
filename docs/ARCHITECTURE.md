# ARCHITECTURE — архитектура системы

Документ фиксирует **структуру системы**: двухэтажную схему, что считается офлайн и что в рантайме, границы модулей, форматы данных и то самое «сменное ядро», ради которого вся обвязка построена независимой от матчера.

---

## Двухэтажная модель: retrieval vs pose

Фундаментальное разделение, на котором держится вся архитектура: в системе есть **два разных механизма**, отвечающих на разные вопросы. Их постоянно путают и пытаются заменить один другим — это ошибка.

| | Этаж 1 — Retrieval | Этаж 2 — Pose |
|---|---|---|
| Вопрос | «ГДЕ примерно?» | «ГДЕ точно и под каким поворотом?» |
| Механизм | эмбеддинг (DINOv2) → ANN | матчинг точек → преобразование |
| Гранулярность | размер клетки индекса | пиксель / субпиксель |
| Скорость | миллисекунды | десятки–сотни мс |
| Устойчивость к appearance gap | высокая | зависит от матчера |
| Даёт метровую точность? | **нет** (по своей природе) | **да** |

**Почему это не «или-или».** Эмбеддинг инвариантен к точному положению — два кадра со сдвигом 20 м дают почти одинаковый вектор, в этом его смысл (устойчивое «место», а не пиксельная геометрия). Поэтому он **не может** дать точность, но идеально убивает грубый поиск. Матчер даёт точность, но перебирать им весь диск ±5 км дорого. Их роли строго разделены: retrieval схлопывает диск в top-K клеток, матчер уточняет позу только на них.

Это же снимает ложную дихотомию «DINO vs матчер»: сильная модель может работать на обоих этажах — глобальным вектором для retrieval и плотными патч-фичами для semantic dense matching на точном уровне.

## Offline vs Runtime

```
OFFLINE (индексация региона, один раз на регион)
────────────────────────────────────────────────
подложка (XYZ-тайлы)
   │  нарезка на перекрывающиеся клетки на нескольких зумах
   ▼
клетки  ──► DINOv2 энкодер ──► векторы ──► FAISS/HNSW индекс  ( + гео-метаданные клеток )
                                              │
                                     «хеш местности» на диске


RUNTIME (на каждый кадр)
────────────────────────────────────────────────
кадр + приор
   │
   ▼
[1] нормализация:   GSD/footprint из камеры · grayscale · CLAHE · ректификация pitch/roll
   │
   ▼
[2] ЭТАЖ 1 retrieval:   кадр → DINOv2 → ANN-запрос → top-K клеток  (+ сигнал уникальности)
   │
   ▼
[3] ЭТАЖ 2 матчинг:     для каждой из top-K → загрузка окна подложки → match() → соответствия
   │
   ▼
[4] pose:               RANSAC similarity (4 DoF) с приором-ограничением → преобразование
   │
   ▼
[5] refinement:         субпиксель (ECC/flow) + цикл переуточнения масштаба (→ уточнение высоты)
   │
   ▼
[6] считывание:         центр/углы через Georef → lat/lon · курс · высота · полигон
   │
   ▼
[7] quality:            фьюжн сигналов → ковариация/эллипс + статус (LOCALIZED / LOW / NOT)
```

Границы этапов совпадают с границами модулей — это делает каждый этап отдельно тестируемым.

## Модули и их ответственность

```
aero_geoloc/
├── geo.py         Web Mercator, Georef, pixel↔lonlat, haversine.       НЕ знает про матчинг.
├── camera.py      Модель камеры: GSD, footprint, интринсики, ректификация наклона.
├── basemap.py     Загрузка/сшивка XYZ-тайлов, кроп, кэш, → Georef.     НЕ знает про матчинг.
├── retrieval.py   DINOv2-эмбеддинги, многомасштабный ANN-индекс, top-K.  [ЭТАЖ 1]
├── matcher.py     ★ СМЕННОЕ ЯДРО ★ интерфейс match() + реализации.       [ЭТАЖ 2]
├── pose.py        Робастная оценка (similarity/RANSAC) + refinement.
├── quality.py     Ковариация, фьюжн доверия, статус/отказ.
├── localize.py    Оркестрация: связывает всё, реализует coarse-to-fine и циклы.
└── testbench.py   Генерация синтетики, метрики точности, калибровка.
```

**Правило зависимостей.** `geo`, `camera`, `basemap` — фундамент, ни от чего в проекте не зависят. `matcher`, `retrieval`, `pose`, `quality` зависят только от фундамента и от общих типов. `localize` зависит от всех и содержит логику оркестрации. Ничто не зависит от `localize`. Такой ациклический граф позволяет тестировать слои по отдельности и подменять реализации.

## ★ Сменное ядро матчинга

Это центральное решение архитектуры. Матчер спрятан за единым интерфейсом; **всё остальное от его внутренностей не зависит**.

```python
class Correspondences:
    pts_q: np.ndarray   # (N,2) точки в кадре
    pts_r: np.ndarray   # (N,2) соответствующие точки в подложке
    conf:  np.ndarray   # (N,)  уверенность на пару (для взвешивания в pose/quality)

class Matcher(Protocol):
    def match(self, query_gray: np.ndarray, ref_gray: np.ndarray) -> Correspondences: ...
```

Реализации (подключаются по фазам из [PLAN.md](PLAN.md)):

| Реализация | Фаза | Когда |
|---|---|---|
| `SIFTMatcher` / `AKAZEMatcher` | 1–3 | синтетика, малый appearance gap; завод пайплайна |
| `LightGlueMatcher` (SuperPoint) | 4 | борт, умеренный gap; быстрый и точный |
| `LoFTRMatcher` / `ASpanFormer` | 4 | detector-free, слабо-текстурные сцены |
| `RoMaMatcher` / `DKMMatcher` | 4 | dense SOTA, тяжёлый кросс-сезон борт↔спутник |
| `DINODenseMatcher` | 4 | плотные DINOv2-фичи, семантическая устойчивость |

Смена матчера = смена одной строки конфигурации. Стенд ([TESTING.md](TESTING.md)) прогоняет любой из них через один и тот же протокол → честное A/B.

## Форматы данных

```python
@dataclass
class Camera:
    image_width: int
    image_height: int
    focal_mm: float | None = None
    sensor_width_mm: float | None = None
    fov_deg: float | None = None          # альтернатива focal+sensor

@dataclass
class Prior:
    lat: float
    lon: float
    sigma_m: float                        # погрешность позиции (до 5000)
    altitude_m: float                     # приблизительная высота (400–800, шире — до 100)
    altitude_sigma_m: float               # погрешность высоты → приор на масштаб
    yaw_deg: float
    pitch_deg: float = 0.0
    roll_deg: float = 0.0

@dataclass
class LocalizationRequest:
    image: np.ndarray | str
    camera: Camera
    prior: Prior
    basemap: str = "esri"

class Status(Enum):
    LOCALIZED = "localized"
    LOW_CONFIDENCE = "low_confidence"
    NOT_LOCALIZED = "not_localized"

@dataclass
class LocalizationResult:
    status: Status
    center_lat: float | None
    center_lon: float | None
    heading_deg: float | None             # курс относительно севера
    altitude_est_m: float | None          # из восстановленного масштаба
    footprint_lonlat: list[tuple] | None  # 4 угла отпечатка
    transform: np.ndarray | None          # 2x3 similarity кадр→подложка
    error_ellipse_m: tuple | None         # (semi-major, semi-minor, angle_deg)
    covariance_m2: np.ndarray | None      # 2x2 ковариация центра
    confidence: float                     # 0..1, откалибровано
    diagnostics: dict                     # инлайеры, RMSE, NCC, top-K расстояния и т.д.
```

`diagnostics` не выбрасываем — это сырьё для стенда, отладки и калибровки.

## Ключевые инварианты (то, что не меняется между фазами)

1. **Модель pose — подобие (4 DoF)** для надира: поворот + единый масштаб + сдвиг. Ограниченность модели сама фильтрует мусор (абсурдный масштаб/поворот отбрасываются). Гомография (8 DoF) — только при заметном неизвестном наклоне.
2. **Масштаб свободен, но с приором** от `altitude_sigma_m` — потому что высота задана с погрешностью; восстановленный масштаб даёт оценку высоты.
3. **Приор позиции — ограничение**, а не подсказка: решение вне диска ±σ штрафуется/отбрасывается (иначе ложняк на повторяющейся местности).
4. **Результат — распределение, а не точка**: всегда ковариация + статус. Отказ — легитимный исход.
5. **Georef — единственный мост «пиксель↔координата»**: все переводы идут только через него, никакой геометрии координат в других модулях.
