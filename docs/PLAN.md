# PLAN — план реализации и тестирования

Документ описывает **пошаговую реализацию** сервиса от простого к сложному и **стратегию тестирования** на каждом шаге. Принцип: каждая фаза даёт работающий, проверяемый артефакт с чёткими критериями приёмки. Не переходим к следующей фазе, пока предыдущая не прошла свои критерии на стенде.

Сквозная идея: **сначала строим полную «обвязку» вокруг простого классического матчера на синтетике, доводим её до конца (включая оценку качества и отказ), и только потом усложняем ядро.** Так мы отделяем сложность инфраструктуры от сложности матчинга и на каждом шаге понимаем, что именно тестируем.

Легенда важности: 🟥 критично для MVP · 🟧 нужно для полноты · 🟩 доработка.

---

## Фаза 0 — Фундамент: геометрия и модель камеры 🟥

**Цель.** Заложить всю геометрию, которую можно проверить **офлайн, без сети и без матчинга**. Это самый дешёвый и самый важный для точности слой — ошибка здесь отравит всё выше.

**Модули.**
- `geo.py` — Web Mercator (EPSG:3857), класс `Georef` (центр lon/lat + зум + размер → `pixel_to_lonlat` / `lonlat_to_pixel`), `ground_mpp`, `zoom_for_mpp`, `haversine_m`.
- `camera.py` — класс `Camera`: `focal_px()`, `K()` (интринсики), `gsd(H)`, `footprint_m(H)`, `tilt_rectification_homography(pitch, roll)`.
- Типы данных: `Prior`, `LocalizationRequest`, `LocalizationResult`, `Status` (см. [ARCHITECTURE.md](ARCHITECTURE.md)).

**Ключевые формулы.**
- `f_px = focal_mm · W / sensor_mm`  (или `f_px = (W/2) / tan(FOV/2)`)
- `GSD = H / f_px`  (метры/пиксель кадра в надир)
- `footprint = GSD · W`
- `ground_mpp(lat, zoom) = 156543.034 · cos(lat) / 2^zoom`  (истинное разрешение подложки)

**Тестирование.**
- Round-trip: `lonlat → pixel → lonlat` совпадает до 1e-6°.
- Сверка `ground_mpp` с эталонной таблицей Web Mercator по зумам.
- GSD/footprint против ручного расчёта на 2–3 конфигурациях камеры.
- `haversine_m` против известных расстояний между городами.

**Критерий приёмки.** Все геометрические юнит-тесты зелёные; конвертации точны до пикселя. Сеть не требуется.

## Фаза 1 — MVP: одиночный кадр, классика, синтетика 🟥

**Цель.** Доказать сквозную геометрию end-to-end на **самом простом входе**: query — это кроп из той же подложки с известными сдвигом/поворотом/масштабом, приор **узкий** (retrieval пока НЕ строим). Матчер — классический. Никакой сети: работаем на заранее скачанном большом растре подложки.

**Модули.**
- `matcher.py` — интерфейс `match(query_gray, ref_gray) → Correspondences (pts_q, pts_r, conf)`; первая реализация `SIFTMatcher` (детектор + Lowe ratio).
- `pose.py` — `estimate_similarity(corr, prior) → Transform` через RANSAC/`estimateAffinePartial2D` (4 DoF: поворот, единый масштаб, сдвиг).
- `localize.py` — минимальная оркестрация: нормализация → match → pose → считывание центра/поворота/масштаба через `Georef`.

**Что НЕ делаем в этой фазе.** Сеть, retrieval, coarse-to-fine, refinement, ковариацию — только скелет «кадр → преобразование → координаты».

**Тестирование (стенд `testbench.py`, ядро).**
- Генератор: берём большой растр подложки, вырезаем query в **известном** центре с заданными поворотом (имитация yaw), масштабом (имитация ошибки высоты), опц. малой перспективой (pitch/roll).
- Метрика: расстояние (м) между истинным и оценённым центром; ошибка восстановленного поворота (°) и масштаба (%).
- Прогон по сетке возмущений: yaw ∈ [0..360], scale ∈ [0.8..1.2], сдвиг центра.

**Критерий приёмки.** На чистой синтетике медианная ошибка центра — доли пикселя → до потолка георефы; ошибка поворота < 0.5°, масштаба < 1%. Пайплайн стабильно сходится без ложняков (приор узкий).

## Фаза 2 — Полный одиночный пайплайн: сеть, coarse-to-fine, refinement, качество 🟥

**Цель.** Довести одиночную локализацию до **боевого качества и честной оценки**, всё ещё на классике и (пока) на синтетике/полусинтетике, но уже с реальной подложкой из сети и с широким приором ±5 км.

**Модули / доработки.**
- `basemap.py` — загрузка и сшивка XYZ-тайлов (Esri World Imagery по умолчанию), кроп по центру, возврат `Georef`. Кэш тайлов на диск.
- Coarse-to-fine в `localize.py`: грубый уровень (весь диск ±5 км в низком разрешении, query даунсемплится до mpp подложки, top-K кандидатов) → точный уровень (маленькое окно вокруг кандидата в максимальном разрешении).
- Приведение масштабов: выбор зума подложки так, чтобы `mpp ≈ GSD`; ресемпл query.
- Ректификация наклона по известным pitch/roll (при заметных углах).
- `pose.py` — **субпиксельный refinement** (`cv2.findTransformECC` / dense-flow) поверх RANSAC-модели.
- **Цикл переуточнения масштаба**: если восстановленный масштаб ≠ ожидаемому → `H_est = scale · H_prior` → перетягиваем подложку на скорректированном зуме → матчим заново (1–2 итерации).
- `quality.py` — фьюжн сигналов (инлайеры, reprojection RMSE, фотометрическое рассогласование после refinement, согласованность масштаба/поворота/позиции с приорами, уникальность лучшего кластера) → **ковариация центра (эллипс ошибки)** + статус `LOCALIZED / LOW_CONFIDENCE / NOT_LOCALIZED`.

**Тестирование.**
- Стенд из фазы 1, но с широким приором ±5 км → проверяем, что приор-как-ограничение и мультигипотезность не дают ложняков на повторяющейся местности.
- **Лестница возмущений внешнего вида** (см. [TESTING.md](TESTING.md)): яркость, блюр, JPEG, цветовой сдвиг «под сезон», подрисованные объекты. Фиксируем **точку перелома**, где классика начинает сыпаться.
- **Проверка калибровки**: заявленный эллипс должен соответствовать фактическому распределению ошибок (не overconfident).
- Регресс на однородных сценах (лес/поле/вода): ожидаем корректный `NOT_LOCALIZED`, а не уверенно-неверную точку.

**Критерий приёмки.** На реальной подложке с широким приором: высокая доля верных локализаций на текстурно-богатых сценах; корректный отказ на бедных; эллипс откалиброван (покрытие ~соответствует номиналу); нет уверенных ложняков дальше σ приора.

## Фаза 3 — Retrieval-этаж: «хеширование местности» 🟧

**Цель.** Убрать дорогой перебор окон на грубом уровне: заменить его на **быстрый ANN-поиск по эмбеддингам**, чтобы диск ±5 км схлопывался в top-K клеток за миллисекунды и система масштабировалась на большие территории. Детально — [RETRIEVAL.md](RETRIEVAL.md).

**Модули.**
- `retrieval.py` — энкодер (DINOv2 глобальный вектор либо Salad/NetVLAD-агрегация), построение **многомасштабного** индекса тайлов подложки (уровни зума под диапазон высот, перекрытие ~50%, ротационная аугментация), ANN-поиск (FAISS/HNSW), запрос кадром → top-K клеток.
- `scripts/build_index.py` — оффлайн-индексация региона.
- Интеграция: retrieval становится грубым уровнем перед геометрическим матчером в `localize.py`.

**Тестирование.**
- Recall@K: доля случаев, где верная клетка попала в top-K, по высотам и типам местности.
- **Калибровка расстояний ANN → флаг отказа**: если top-1 резко ближе остальных — уникально; если top-K сидят кучно — самоподобие, поднимаем `NOT_LOCALIZED`. Проверяем, что этот сигнал согласуется с фактической разрешимостью.
- Скорость запроса и объём индекса на регион.

**Критерий приёмки.** Высокий Recall@K при малом K; retrieval не теряет верную клетку чаще матчера; сигнал уникальности из ANN коррелирует с реальной успешностью локализации. Сквозная точность не хуже фазы 2, скорость — заметно выше.

## Фаза 4 — Обученный матчер и реальные снимки с борта 🟧

**Цель.** Пройти точку перелома appearance gap: заменить **только ядро** матчинга на обученное, не трогая обвязку, и валидировать на реальных бортовых кадрах.

**Модули / доработки.**
- `matcher.py` — новые реализации за тем же интерфейсом: `LightGlueMatcher` (SuperPoint), `LoFTRMatcher` (detector-free), `RoMaMatcher`/`DKMMatcher` (dense, для тяжёлого кросс-сезона). Опц. ансамбль с фьюжном соответствий. Опц. TensorRT.
- Нормализация под appearance gap: CLAHE, матчинг по структуре (границы/дорожная сеть), опц. плотные DINOv2-фичи как semantic matching.

**Тестирование.**
- Прогон лестницы возмущений на обученном матчере: показываем, что точка перелома сместилась заметно дальше классики.
- Реальные данные: бортовые кадры с GPS/INS как ground truth → ошибка центра в метрах на разных сезонах/освещении.
- A/B матчеров за единым интерфейсом на одном стенде.

**Критерий приёмки.** На реальных кадрах с умеренным appearance gap — устойчивая локализация там, где классика уже отказывала; метрики на стенде воспроизводимы; переключение матчера не требует изменений в остальном коде.

## Фаза 5 — Низкие высоты: последовательностный режим 🟩

**Цель.** Сделать жизнеспособной локализацию на 100–250 м, где одиночный кадр из ±5 км — иголка в стоге и часто плохо поставлен.

**Модули / доработки.**
- Визуальная одометрия кадр-к-кадру (накопление траектории).
- Периодическая абсолютная привязка к карте там, где сцена уникальна (сигнал уникальности из retrieval), и распространение через **EKF/pose-graph**.
- Опц. учёт рельефа (DEM/DSM) для коррекции параллакса высоких объектов.
- Правило режима по высоте/σ приора: ниже порога footprint/патча — переключение на последовательностный режим или флаг низкого доверия.

**Тестирование.**
- Синтетическая траектория с известным маршрутом → дрейф VO, точность на якорях, устойчивость к бедным кадрам между якорями.
- Проверка, что редкие уверенные фиксы «якорят» дрейф, а бедные кадры не заставляют угадывать.

**Критерий приёмки.** На низковысотной последовательности траектория стабильна и ограничена по дрейфу; одиночные бедные кадры не порождают уверенно-неверных точек.

## Принципы, сквозные для всех фаз

- **Стенд раньше кода фазы.** Метрика точности и калибровки существует до того, как усложняем алгоритм — иначе «улучшения» неизмеримы.
- **Единый интерфейс матчера.** Всё выше матчера (георефа, pose, refinement, quality, retrieval, стенд) от него не зависит.
- **Честный отказ дороже красивой точки.** Молчаливая ошибка хуже `NOT_LOCALIZED`. Каждая фаза проверяется не только на «попал», но и на «корректно отказался».
- **Синтетика не покажет appearance gap.** Класс отказов «борт↔спутник» моделируется специально (лестница возмущений), иначе переход синтетика→борт будет «на глаз», а не измеримым.
