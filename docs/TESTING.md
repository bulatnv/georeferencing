# TESTING — тестирование и валидация

Раз точность — приоритет №1, метрика точности и калибровки должна существовать **до** усложнения алгоритма, иначе «улучшения» неизмеримы. Этот документ описывает синтетический стенд, метрики, проверку калибровки доверия и измеримый переход синтетика→борт.

---

## Синтетический стенд (ядро валидации)

Идея: генерируем query кропом подложки в **известном** центре, накладывая известные возмущения, и меряем, насколько точно пайплайн восстановил истину. Так у нас есть ground truth без разметки.

**Генератор одного примера:**
```
1. Взять большой растр подложки (или тайлы) с известной Georef.
2. Выбрать истинный центр (lat0, lon0) и вырезать патч.
3. Наложить известные возмущения геометрии:
   - поворот  θ_true      (имитация yaw)
   - масштаб  s_true      (имитация ошибки высоты, из диапазона altitude_sigma)
   - сдвиг центра         (кадр между клетками)
   - опц. малая перспектива (pitch/roll)
4. Опц. наложить возмущения внешнего вида (см. «лестницу» ниже).
5. Сформировать приор: центр = (lat0,lon0) + случайный сдвиг в пределах σ; высота с погрешностью.
6. Отдать в localize(), сравнить с истиной.
```

**Первичные метрики (геометрия):**
- ошибка центра, **метры** (главная) — `haversine(true, est)`;
- ошибка поворота, градусы;
- ошибка масштаба/высоты, %;
- доля успешных локализаций (по статусу).

Прогон — по сетке: `θ ∈ [0..360]`, `s ∈ [1−k .. 1+k]`, сдвиги центра, типы местности.

**Ожидание на чистой синтетике** (фазы 1–2): ошибка центра — доли пикселя → до потолка георефы подложки; поворот < 0.5°, масштаб < 1%. Если нет — баг в геометрии/pose, а не в матчере.

## Лестница возмущений внешнего вида (переход синтетика→борт)

Чистая синтетика **не покажет** appearance gap — она из того же источника, что подложка. Класс отказов «борт↔спутник» надо моделировать специально, постепенно приближая query к реальному кадру:

| Уровень | Возмущение | Что имитирует |
|---|---|---|
| L0 | нет | идеальная синтетика |
| L1 | яркость/контраст, гамма | экспозиция, время суток |
| L2 | блюр, шум, JPEG-артефакты | оптика, сжатие, сенсор |
| L3 | цветовой/спектральный сдвиг | сезон, другой сенсор |
| L4 | локальные изменения: подрисованные/убранные объекты | новые дома/дороги, возраст подложки |
| L5 | синтетический параллакс высоких объектов | рельеф/здания на низкой высоте |
| L6 | реальные бортовые кадры с GPS/INS | настоящий gap |

**Точка перелома.** Для каждого матчера фиксируем уровень, на котором доля успешных локализаций/точность резко падают. Это и есть измеримый сигнал «классика исчерпана, пора включать обученный матчер» (фаза 4). У обученного матчера точка перелома должна сместиться заметно дальше — это и есть критерий, что замена ядра оправдана.

## Проверка калибровки доверия

Сервис отдаёт не точку, а точку + эллипс + статус. Значит нужно проверять, что **заявленная неопределённость честная** (не overconfident):

- **Покрытие эллипса.** На большом наборе доля случаев, где истинный центр попал внутрь заявленного 1σ-эллипса, должна быть ~соответствующей номиналу (≈39% для 2D 1σ, ≈95% для 2.45σ). Систематическое занижение эллипса = overconfidence, это баг оценки.
- **Reliability-диаграмма.** Бьём по бинам `confidence`; в каждом бине эмпирическая доля успехов должна совпадать с заявленной уверенностью.
- **Корректность отказа.** На бедных/однородных сценах и на неоднозначных конфигурациях ожидаем `NOT_LOCALIZED`, а не уверенно-неверную точку. Метрики: доля «молчаливых ошибок» (уверенно и неверно) — должна быть минимальной; это важнее средней точности.

---

## Метрики retrieval (Этаж 1)

- **Recall@K** по высотам и типам местности: доля случаев, где верная клетка в top-K (при малом K).
- Согласованность **сигнала уникальности** (зазор top-1/top-2, разброс top-K) с фактической успешностью локализации.
- Скорость запроса и объём индекса на регион (влияние многомасштабности и ротационной аугментации).

---

## Тесты по фазам (сводка)

| Фаза | Главная проверка | Критерий |
|---|---|---|
| 0 | геометрия офлайн | round-trip до пикселя; GSD/mpp против эталона |
| 1 | сквозной скелет на чистой синтетике | медианная ошибка центра — доли пикселя |
| 2 | полный пайплайн + качество, широкий приор | нет уверенных ложняков > σ; эллипс откалиброван; корректный отказ |
| 3 | retrieval | высокий Recall@K; сигнал уникальности коррелирует с успехом |
| 4 | обученный матчер, борт | точка перелома дальше классики; ошибка в метрах на реальных данных |
| 5 | последовательность, низкая высота | ограниченный дрейф; нет уверенно-неверных точек между якорями |

## Регрессия и воспроизводимость

- Фиксированные seed’ы генератора → детерминированные наборы.
- Золотые наборы по типам местности (город/пригород/поля/лес/вода) — каждый прогоняется на каждом изменении.
- Единый протокол стенда для всех матчеров → честное A/B за одним интерфейсом (`Matcher`).
- Все `diagnostics` из `LocalizationResult` логируются — сырьё для разбора провалов и калибровки.
