# PIPELINE — стадии обработки

Пошаговое описание рантайм-пайплайна: что вычисляется на каждой стадии, по каким формулам и почему именно так. Стадии соответствуют модулям из [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Стадия 0 — Что известно ещё до матчинга

До всякой сверки входные данные задают геометрию поиска и резко сужают задачу.

**Масштаб кадра (GSD).**
```
f_px = focal_mm · W / sensor_mm        (или  f_px = (W/2) / tan(FOV/2))
GSD  = H / f_px                         [м/пиксель]
```

**Footprint** (размер кадра на земле): `footprint = GSD · W`.

**Разрешение подложки** на зуме `z` и широте `lat`:
```
mpp(lat, z) = 156543.034 · cos(lat) / 2^z    [истинные м/пиксель]
```

**Область поиска**: `footprint + 2·σ_позиции`. При σ = 5 км это ~10 км — доминирует неопределённость приора.

**Что из этого следует.** Кадр ~200 м ищется в области ~10 км — отношение до ~49 по линейному размеру (и растёт до ~294 на низких высотах). Это «иголка в стоге»: матчить в лоб на полном разрешении нельзя, отсюда retrieval + coarse-to-fine. Числа по высотам:

| Высота | footprint | GSD кадра | поиск/footprint (10 км) |
|---|---|---|---|
| 600 м | 205 м | 0.20 м/px | 49 |
| 250 м | 85 м | 0.083 м/px | 118 |
| 150 м | 51 м | 0.050 м/px | 196 |
| 100 м | 34 м | 0.033 м/px | 294 |

## Стадия 1 — Нормализация входов

Приводим кадр и подложку к общему виду, чтобы матчер сравнивал сравнимое.

- **Grayscale + выравнивание освещения (CLAHE).** На синтетике почти не нужно, но закладываем сразу — для борта критично (тени, сезон, экспозиция).
- **Ректификация наклона.** Если pitch/roll заметны и известны — переводим кадр в надир-эквивалент гомографией наклона (допущение плоской земли):
  ```
  H_tilt = K · R(pitch, roll) · K⁻¹
  ```
  После этого дальше работаем с чистым подобием. Для |pitch|,|roll| < ~10° приближение хорошее.
- **Приведение масштаба.** Выбираем зум подложки так, чтобы `mpp ≈ GSD`, и ресемплим кадр к разрешению подложки. Совпадение масштабов резко повышает устойчивость матчинга (особенно для классики).

**Про yaw — две стратегии** (см. также [ARCHITECTURE.md](ARCHITECTURE.md)):
- *доверяем yaw* → предповорот кадра на −yaw (север вверх), остаточный поворот мал, поиск уже;
- *не доверяем* → rotation-invariant матчер находит полный поворот, yaw идёт только на проверку согласованности.

## Стадия 2 — Грубый уровень (retrieval, «ГДЕ примерно»)

Задача — не точность, а отсечь 99% карты и выдать **top-K кандидатных клеток**. Именно K (несколько), а не одна — чтобы поймать неоднозначность на самоподобной местности.

- Кадр → DINOv2 → вектор → ANN-запрос к индексу местности → top-K клеток.
- Побочно получаем **сигнал уникальности**: распределение расстояний до соседей. top-1 резко ближе → место уникально; top-K кучно → самоподобие, заранее занижаем доверие.

Детали индекса (многомасштабность, ротация, калибровка) — [RETRIEVAL.md](RETRIEVAL.md).

> В ранних фазах ([PLAN.md](../PLAN.md), фазы 1–2) retrieval ещё не построен; грубый уровень делается перебором окон подложки или на узком приоре. Логика top-K и сигнала уникальности сохраняется.

---

## Стадия 3 — Точный уровень (матчинг, «ГДЕ точно»)

Для каждой из top-K клеток тянем **маленькое окно подложки в максимальном разрешении** и вызываем сменный матчер:

```
corr = matcher.match(query_gray, ref_window_gray)   # → pts_q, pts_r, conf
```

На выходе — сотни–тысячи кандидатных соответствий (с мусором, который вычистит следующая стадия). Точность рождается именно здесь, на нативном масштабе.

---

## Стадия 4 — Робастная оценка позы

Оцениваем преобразование `кадр → подложка` устойчиво к выбросам.

- **Модель — подобие (4 DoF)**: поворот θ, единый масштаб s, сдвиг (tx, ty). Для надир↔надир это физически правильно, и ограниченность модели — сама по себе фильтр.
- **RANSAC / MAGSAC** (`estimateAffinePartial2D`). Гипотезы отбрасываются, если:
  - масштаб `s` далёк от ожидаемого `GSD/mpp` (с допуском от `altitude_sigma_m`);
  - поворот `θ` далёк от yaw (если yaw используется как приор);
  - центр решения выходит за диск ±σ приора.
- Из матрицы `M = [[a,b,tx],[c,d,ty]]`: `s = √(a²+c²)`, `θ = atan2(c, a)`.

Заметный неизвестный наклон → вместо подобия берём гомографию (8 DoF), но платим устойчивостью.

---

## Стадия 5 — Субпиксельный refinement + цикл масштаба

**Главный рычаг точности.** После робастной модели дотягиваем фотометрически:
- `cv2.findTransformECC` или dense-flow-уточнение минимизируют рассогласование внешнего вида в области инлайеров. Это превращает «точность в 5 px» в субпиксель. На борту refinement делаем по структуре (градиенты/границы), а не по сырой яркости.

**Цикл переуточнения масштаба** (важно из-за погрешности высоты):
```
если |s − 1| велико:                      # масштабы кадра и подложки разошлись
    H_est = s · H_prior                    # уточняем высоту
    перетянуть подложку на зуме под H_est  # mpp снова ≈ GSD
    заново match + pose                    # инлайеров и точности больше
повторить 1–2 итерации
```

Восстановленный масштаб напрямую даёт оценку высоты: `H_est = s · H_prior` (т.к. `GSD ∝ H`).

## Стадия 6 — Считывание результата

Из финального преобразования и `Georef` подложки:

- **Центр**: центральный пиксель кадра → (через `M`) пиксель подложки → `georef.pixel_to_lonlat` → `lat/lon`.
- **Отпечаток**: 4 угла кадра тем же путём → полигон на карте.
- **Курс**: из θ — поворот кадра относительно севера.
- **Высота**: из s — `H_est`.

Всё «пиксель↔координата» идёт только через `Georef` — единственный мост (инвариант из [ARCHITECTURE.md](ARCHITECTURE.md)).

## Стадия 7 — Оценка качества и статус

Результат — **распределение, а не точка**. Складываем независимые сигналы во фьюжн:

- число и доля инлайеров RANSAC;
- reprojection RMSE инлайеров (px → м через mpp);
- остаточное фотометрическое рассогласование после refinement (NCC/SSIM выровненного патча);
- согласованность масштаба / поворота / позиции с приорами (в единицах σ);
- **уникальность** — насколько лучший кластер (и top-1 клетка retrieval) превосходит второй.

Из остаточных невязок инлайеров и их пространственного разброса **пропагируем ошибку в ковариацию центра** (2×2, метры) → эллипс ошибки (semi-major/minor, угол; CEP).

**Статус:**
- `LOCALIZED` — доверие выше порога, эллипс мал;
- `LOW_CONFIDENCE` — привязка есть, но неопределённость велика/сигналы противоречивы;
- `NOT_LOCALIZED` — ниже порога либо неоднозначность (две далёкие позиции объясняют кадр одинаково). **Честный отказ дороже уверенно-неверной точки.**

Пороги и калибровка эллипса проверяются на стенде — [TESTING.md](TESTING.md).
